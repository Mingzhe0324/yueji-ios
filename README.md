# 月记 · 原生 iPhone App

这是 SwiftUI 原生项目源码，不是网页，也不是已签名、可直接安装的 IPA。优先实现 Apple Pay → 快捷指令 → 本机账本。无需账本服务器、网页令牌或付费开发者账号。安装与首次自动化配置仍需要你在自己的设备完成。

## 1.6（build 10）六项功能与轻动效

1. 自定义分类：设置 → 管理分类，新增名称、图标、颜色；支持编辑改名。分类接入手动账目、固定消费、商户记忆规则与统计。改名同步关联记录；仍被使用的分类需先改相关账目才能删除。内置分类保留，自定义名称不自动翻译。
2. 月度消费对比：概览 → 月度消费对比；显示所选月与上一自然月的个人净消费、分类条形图及增减金额/百分比。上月为零时显示新增金额，不计算无限百分比；未结束月份不按天折算。
3. 指定退款分配：账目 → 退款记录 → 指定退款分配，填自己及各朋友金额，留空为零。合计须等于实际退款，每人不可超过剩余份额；已还清朋友对应款项会变为需退给朋友。可在退款历史查看分配，原比例分配仍保留。
4. 账本筛选：账本 → 筛选，分类、来源、金额上下限与商户搜索共同生效。金额按入账 MYR 总付款、退款前计算，包含朋友份额；只筛选当前月份。可以一键清除。
5. 常用行程资料：油费计算器填写油耗、油价及朋友姓名后点击保存，下次打开自动填入；可清除。里程、停车费及过路费不保存到常用资料，避免把上次行程费用误计入新行程。填写好的姓名也传入账单确认页。
6. CSV 导出：设置 → 数据与备份 → 导出 Excel / CSV；选择月份或全部、消费或分账明细。UTF-8 BOM、标准双引号转义及公式字符串防护，便于 Excel 打开。CSV 不是 JSON 备份，不提供 CSV 恢复。

动画：玻璃卡片轻淡入、月份文字过渡、金额数字变化、筛选列表及对比图变化；分类图标使用配色。遵循 iPhone 减少动态效果设置，无持续循环动画。

兼容现有 v1–v3 JSON 备份；自定义分类及行程常用资料保存在新备份中。新增这些资料后，旧版 App 不保证能读取，恢复请使用 1.6 或更新版。原自动记账、通知与每日提醒均保留。

验证：项目结构、Swift 语法、版本及工作流静态检查。新增 XCTest 覆盖分类引用同步、指定退款限额与原子性、月度个人净消费、筛选交集、行程资料和旧备份、CSV 转义与月份选择。此环境没有 Xcode，未执行原生编译、XCTest 或手机动画验证。上传完整源码并运行 Actions，应显示 Source: 1.6 (10)，IPA 名为 YueJi-1.6-build10-unsigned.ipa。

## 1.5（build 9）分类、分账、恢复与每日提醒

- 商户分类记忆：修改已有消费的分类，保存后记住该商户；后续 Apple Pay 优先使用规则。设置中可查看、左滑删除规则。规则随账本备份。
- 自动记账结果通知：设置 → 通知与每日提醒，开启「自动记账结果通知」并保存、允许通知。成功显示 MYR 金额、商户和分类；重复跳过与失败原因分别提示。无法检测未调用月记的交易。通知失败不会回滚成功记账。
- 已结清筛选：分账首页、按朋友汇总均有「未结清 / 已结清」，保留原消费及还款、返款记录。
- 朋友账单分享：朋友明细 → 分享朋友账单，选月份或全部，预览后用系统分享。按消费月份选账，列出所选账目截至目前的还款、返款、待还及待退金额，不含其他朋友姓名及份额。
- 备份恢复预览：显示备份生成时间（旧文件可能没有）、账目数量、消费日期范围和固定项目数。确认后才恢复；恢复前的数据另存一份，独立于 30 份自动备份，可在设置中找回。下次恢复会替换这份恢复副本。通知偏好保留在当前手机，不随账本导入。
- 每日提醒：设置 → 通知与每日提醒，打开开关、选择时间（默认 21:00）、点保存并允许通知。每天一次，已有账目也提醒。修改语言后重新保存通知设置，更新提醒文字。系统专注模式可能影响展示。

验证：通过项目结构、Swift 语法、版本与工作流静态检查；新增分类规则/旧备份/分享隔离/恢复副本轮换 XCTest，未在本机执行。需 GitHub Actions 运行 Xcode 编译和全部测试，再在 iPhone 验证通知授权、改时间、关闭提醒、锁屏展示及实际 Apple Pay 通知。Source 应为 1.5 (9)，成功 IPA 为 YueJi-1.5-build9-unsigned.ipa。

## 1.4（build 8）油费入账

停车费、过路费默认留空，左侧名称始终显示；空值按零计算。油费计算器新增「保存到账本」，预填合计、交通分类及分账份额，在原生记账页面填写行程名称、日期和真实朋友姓名后保存。人数可设为 0，全部计为个人消费。取消确认不会产生账目，保存后返回上级页面，同一草稿 ID 不会重复新增。

「需退回」改为「我需退给朋友」，说明它来自退款与朋友已付款的自动计算。实际返款仍由每笔账目的「退回朋友」记录。

若加油或行程已通过 Apple Pay 等方式入账，请在原账目分账，避免重复记账。本次保留原有账本格式。静态检查不等于 Xcode 构建及设备验证；上传完整项目后运行 Actions，确认 Source: 1.4 (8)。

## 先看安装说明

打开 `Windows安装与ApplePay设置.md`。免费路线是：自己的公开 GitHub 源码仓库 → GitHub Actions 云端编译 → Windows AltStore Classic 签名安装 → iPhone 配置交易自动化。

公开仓库的标准 GitHub 托管 runner 当前免费。不要选择付费 larger runner。免费 Apple ID 侧载通常每 7 天要刷新签名，过期后 App 无法打开，记账也不能依赖它继续工作。云端编译只用于生成 App；日常账本保存在手机。

## 数据与自动化边界

- App 不直接读取钱包或银行历史；只记录快捷指令交给它的输入。交易触发及可用字段受 iOS、卡片和付款方式影响。
- 不自动补录漏掉的交易，不自动识别退款或撤销；失败/取消付款不得当成成功支出传入。
- 优先用稳定的原始交易标识去重；没有标识时按「交易时间到秒 + 商户 + 金额 + 币种」去重。同秒同商户同金额的不同付款可能被合并。使用当前时间代替原始时间时，重新执行不能可靠去重。
- 本地备份不等于云备份；卸载会删除账本和本地备份。建议定期导出到 iCloud Drive。导出文件包含交易及朋友姓名，请自行保管。
- 此版本保存原生 v3 JSON，并兼容读取旧版原生 v1/v2 备份；不直接导入之前网页版本的备份。
- 重启后至少解锁一次；锁屏、后台运行和签名状态都需实机测试。不能承诺所有付款方式均被捕获。

`.github/workflows/build-ios.yml`：手动触发的云端测试与 IPA 构建，不需要上传 Apple ID 或证书。
