# 店铺地点：Apple 资料与 Google Maps 链接

本实现不调用 Google Places API 或 Maps Static API，不需要 Google API Key 或新增 Supabase 函数。

## 查看地点

- 优先使用已保存的 Apple 店铺标识；没有标识时，用店名、地址与坐标匹配店铺。
- 有坐标时显示地图；没有坐标时不显示无关的区域地图。匹配不唯一时，由用户选择正确分店。
- 查看模式获得店铺标识后自动打开 Apple 原生资料页（iOS 18+），照片由 Apple 决定是否提供；编辑模式保留手动打开按钮。
- Apple 照片不会被提取到月记自制卡片，也无法判断店铺是否有照片。
- “去 Google Maps 看照片”按钮按店名和地址打开 Google Maps 搜索；照片取决于 Google 收录情况。不会自动跳出月记。
- 查看和匹配结果仅作预览，不会自动修改原账目地点。
- 自动匹配使用交易商户名、保存坐标与地址，不会为旧账目请求当前定位。自动采集的位置需在交易时间前后 5 分钟内、精度不超过 100 米；仅有街道而无门牌号的地址不能自动关联。
- 店名标准化后完全一致、500 米内只有一个相同店名候选且距离不超过 100 米时才自动预览。商场内或多分店等不确定情况保留候选列表供选择。

## 部署

需重新构建并安装 iOS App。收据店铺地址／电话识别还需重新部署 `receipt-gemini`（完整 `handler.mjs` 与现有 `index.ts`）；不需要新增 Secrets 或执行 SQL。旧后端仍可扫描收据，但不会自动返回新的地址／电话字段。
如果之前部署了旧 Google 功能，可自行清理不再使用的 `google-places` Edge Function、`GOOGLE_PLACES_API_KEY` 和 `GOOGLE_MAPS_STATIC_API_KEY` Secrets。本次更新不会删除远端资源。

## 确认记忆、别名与收据核对

- 在账目编辑中选择店铺并保存后，记录“账目商户名称 → Apple 分店”的确认关系。未保存的预览、旧版本未明确标记的地点不参与记忆。关系来自当前账本；删除地点或原账目即可移除该条依据，不跨账本学习。
- 相同商户别名只参考交易保存位置或地址附近 500 米内的确认记录，并重新查询地图资料；多个已确认分店同时在附近时不自动关联，不因历史记录而跳过名称、距离及收据校验。
- Gemini 只提取收据上印出的店铺分店地址和营业电话，不提取顾客地址／电话。核对页可更正或清空后保存。本机 OCR 不自动提取这两个字段，可在核对页填写。
- 收据地址会忽略标点、大小写等格式差异后核对；电话兼容马来西亚 `+60`、`0060` 与本地 `0` 前缀。提供的字段与地图不一致或地图缺少相应资料时，仅显示候选供确认。不会用 AI 猜测缺失的地址和电话。
- 店铺照片的可用性仍由地图服务决定。

## 界面动效验收

- iOS 18+ 从账本打开消费、收入、通知或结算详情时使用原生缩放过渡；返回后原账目仍可操作。系统“减少动态效果”或关闭应用动画时使用普通导航。
- 切换月份、分类或来源时保留现有列表过渡，按筛选组合记住最近浏览的账目；返回同一组合时恢复到该条记录，记录不存在则回到筛选栏。仅在当前账本页面会话内保留，最多约 24 组。
- 地点匹配时显示加载状态，无坐标时显示占位卡；获得坐标后淡入地图。减少动态效果时关闭淡入。
- 地点显示“正在匹配／已确认分店／已匹配 · 可核对／地址待核对／待选分店”，自动匹配不冒充用户确认。
- Apple 店铺照片仍由原生资料页管理，地图本身不变成照片卡片；应真机检查有照片和无照片的店铺、网络失败和多分店候选。
