# Overview toolbar and spending meter motion

Overview Add Entry now uses a native trailing navigation-toolbar plus, alongside More tools, matching the ledger's entry point. The bottom floating action and its safe-area panel are removed. The existing sheet presenter, duplicate-tap guard, overview.manualEntry accessibility identifier and dashboard.add guide target remain. The toolbar owns its system appearance, with no second glass surface or custom shadow. Existing shared sheet, tab-bar, grouped surface and native button styles continue to follow the system theme and accessibility preferences.

SpendingMeter now holds a rendered fraction so newly inserted category/budget bars can animate from zero. After one cancellable sixteen-millisecond yield for initial layout, a finite smooth450ms animation reveals the target. Later amounts/month changes animate toward the new fraction. Stable row state avoids resetting an existing bar when it merely reappears. Reduce Motion displays the actual fraction directly and synchronizes the stored value without animation. Calculations and money values are unchanged; there are no repeating timers, blocking sleeps or navigation animations added.

The UI-test viewport helper no longer treats overview.manualEntry as a bottom obstruction, since the native navigation bar already defines the upper boundary. All four transaction regression cases remain. Local validation covers project structure, Swift syntax and diff checks only. Native tests and a real-device review of first appearance, month changes, light/dark modes, large text and Reduce Motion remain required. This adopts the platform's native presentation rather than promising pixel-identical results or a fixed frame rate across hardware.
