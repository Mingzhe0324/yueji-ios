# Receipt, ownership and completion motion

This pass adds the five requested feedback effects without changing saved financial data or calculation rules.

- Receipt details use a shared disclosure in transaction details and editing. Its height opens with a short system transition; original lines reveal top-to-bottom within roughly half a second. At most 41 text blocks are animated, with the entire remaining text preserved in the final block. Sharing still uses the untouched original summary. Reduce Motion displays the text immediately. Closing cancels the entrance task.
- Budget colors interpolate over 0.55 seconds in the amount, badge and meter. Below 80% is blue, 80% through exactly 100% is amber, and spending above the budget is red. The existing status text and percentage supplement color. Progress and color animations remain scoped to the meter; Reduce Motion removes interpolation.
- Item ownership choices have a moving selection background when a single owner/fallback is selected. Multiple owners receive separate highlighted backgrounds. Selecting an owner is immediate and uses the existing binding and validation. A live preview uses `ItemOwnership.friendAmounts` and conserves the original integer cents. It is explicitly labelled as the item subtotal **before charges**; the existing transaction split summary continues to include allocated charges. Summary amounts now use numeric transitions.
- Reimbursement status uses one shared capsule in transaction rows, the reimbursement list and reimbursement detail. Receipt and outstanding amounts animate, the progress bar fills, and completion changes the clock to a checkmark. Feedback happens after the existing successful save; the existing `showSaved` success haptic is reused rather than firing a second haptic on appearance. Undoing a receipt returns the status to pending.
- Successful deletion undo publishes a transient feedback event containing the affected expense/notice IDs. This is not saved in the ledger or backup. The existing projection commit animates returning rows in their chronological position; restored rows receive a short, noninteractive tint that fades away. Failed restore does not publish a success event. The highlight is limited to recent restores, does not replay on ordinary refreshes, and its cancellable task cannot change financial data.

Validation available on Windows is project/resource integrity, Swift syntax parsing and diff review. Native compilation, the retained transaction/financial/banner regressions, and physical-device motion checks remain required through macOS/iPhone. No test gates or CI deadlines were changed.

Device checks: expand/collapse long and short receipts repeatedly; test 79%, 80%, 100% and over-budget values; select self, friends, multiple owners and fallback with odd-cent amounts; complete a claim, undo a receipt, and reopen a completed claim; delete and restore manual/automatic records, including multiple deletions and a rejected stale restore. Repeat in dark mode, large text and Reduce Motion. Confirm restored highlights consume no taps and that cancel/save preserves drafts during ownership navigation.
