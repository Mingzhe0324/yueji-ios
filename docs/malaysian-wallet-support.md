# 马来西亚银行与钱包账户

## Grab Visa 扣卡通知

已适配用户提供的 `Your Visa … has been charged MYR … for booking …` 完整通知格式。来源传入 `Grab`，或标题为 `Grab`；解析结果使用独立来源 `Grab Card`、商户 Grab、卡尾号及订单编号，不归类到 GrabPay。

在实际付款卡对应的账户设置「自动记账来源 = Grab Card」，填写卡尾号。仅来源、尾号唯一匹配时自动入账；钱包账户不参与此匹配，未匹配或多匹配均待确认。该来源设置会替代此账户原先的自动来源，当前账户模型只有一个来源绑定。不要把银行卡尾号和存款账号尾号混淆。

`currently on hold` 和预授权文字被忽略。同一来源、卡尾号、订单编号去重；跨来源仍沿用原有金额、商户或参考号及 120 秒时间窗口检查，不能保证识别延迟到达、商户名不同的银行通知。没有从通知截图推算交易日期，使用传入或接收时间。

新增 XCTest 覆盖匹配、未绑定、重复订单、钱包隔离、尾号冲突和预授权。测试使用虚构卡尾号和订单号；Windows 未执行 XCTest，须在 Xcode 运行。

账户选择新增 GrabPay、ShopeePay，以及 BSN、Bank Rakyat、Agrobank、Bank Pertama。AEON Bank 已在数字银行分类中。

GrabPay、ShopeePay 的规范名称与带空格别名已接入通知来源识别和账户自动关联。添加账户后，用户需明确选择「自动记账来源」；默认关闭，未自动授权扣减。AEON Bank 沿用已有来源映射。同一来源多个账户仍需尾号或人工选择。

仅处理用户导入的通知，不读取其他 App 的通知权限、不连接银行、不自动同步钱包余额。使用现有完整付款语法及核对流程，未知格式留待核对；充值、退款和订单通知不会因钱包名称而成为消费。Grab/Shopee 泛用名称没有映射到钱包，避免把订单或其他支付方式误标为 GrabPay/ShopeePay。

新增的 XCTest 使用合成通知验证账户隔离、余额、非交易拒绝和来源冲突，并非真实服务商模板。Windows 仅验证 Swift 语法、项目资源与语言模板；完整 XCTest 需 Xcode 执行。没有新增钱包 PDF 账单解析器，也没有声称覆盖所有真实通知格式。
