# Reimbursement management

An expense can optionally carry a reimbursement claim with a recipient, claimed MYR amount and dated receipt history. Add/edit expense includes the claim fields; saved transaction details link to claim management. Overview's tools include an all-month reimbursement list with pending/completed filters, outstanding advances and received totals. Overview and ledger display outstanding claims separately from personal spending.

As requested, claimed amounts leave personal spending and budgets immediately. Receiving reimbursement changes only received/outstanding status and never creates income or deducts spending a second time. Original payment, gross personal share, merchant refunds, friend shares and settlement debt stay intact. A separate `personalSpending` projection drives overview, ledger summaries, collection totals, monthly/category comparison and budget alerts. Multi-category spending allocates the remaining personal spending proportionally within the existing item capacities; claims are transaction-level, not per-item reimbursement allocations.

Claims are limited to the user's net paid share. Friend-paid entries cannot be claimed in this first version. Changes to a refund/share that would leave less personal liability than an existing claim are rejected with an instruction to adjust the claim first; refund insertion validates the candidate before mutating the ledger. Receipt amount/date/identity/count bounds reject overpayment, duplicate IDs and invalid dates. Reimbursement edits and receipt mutations compare the expected full transaction to prevent stale writes. Removing a claim with receipts requires explicitly undoing its receipts first. Receipt undo corrects bookkeeping only and does not move funds.

Claim and receipt editors use native sheets, stable Save feedback, shared keyboard focus and the existing dirty-swipe confirmation. List preparation runs in an actor. Manual and automatically recorded expenses use the same optional metadata and editor; reimbursement receipt entry is manual, and does not automatically resolve or match a separate bank/TNG incoming notification.

Old records decode the new optional field as nil and retain existing spending figures. Backups retain claims and all receipt IDs/dates. CSV appends claim recipient/claimed/received/outstanding totals, report spending and receipt history while preserving the previous column meanings. Existing delete/undo records retain full expense metadata.

Regression tests cover reporting/category totals/budget exclusion, payment/debt invariance, partial/full/undo receipts, invalid and stale mutations, refund interaction, backup/CSV and deletion undo. Local validation consists of project reference checks and Swift syntax checks on Windows. Native XCTest/Swift compilation, rendered UI, keyboard and clean/dirty sheet gesture checks remain required on macOS/iPhone. No long-running CI stage or timeout was added.
