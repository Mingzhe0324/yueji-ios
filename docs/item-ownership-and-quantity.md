# Receipt-style item entry and ownership

Item entry and editing now use a unit price, integer quantity (1–999), calculated line total, category and ownership selector. Existing amounts load as one unit, so opening and saving old records does not multiply or round them. Details keep items expanded and show quantity × unit price, line total, category and owners. The same fields and calculation serve manual entries, saved automatic entries and pending payment confirmation.

Ownership is optional for old records. All unassigned items retain the transaction's existing split; once item ownership is chosen, every item must be assigned before saving. The picker supports me, a friend, or multiple people sharing that item's line total equally. Friends can be selected from existing names or added. Whole-transaction split controls are hidden while item ownership is in use; a summary shows the derived shares. Selecting the whole-transaction option for every item returns to the existing split behavior.

Money is calculated in integer cents. Friends receive remainder cents in selection order, consistent with existing equal-share behavior. Derived shares preserve existing share IDs. Per-person category reports use the owned item amounts; refunds are allocated across that person's item capacities. Legacy items continue using the original proportional allocation and identify it as proportional in details. Quantity and ownership survive JSON backups; CSV item descriptions include them when present.

Item reallocation requires undoing existing refunds/repayments first. Existing active-settlement protection still applies. Friend-paid purchases retain the current model's two-party restriction: me and the payer. Quantity changes never silently change the recorded transaction total; item totals must match it before saving. Invalid ownership, mixed assigned/unassigned items, invalid quantities, overflow, mismatched derived shares and fractional-cent unit prices are rejected.

Nine new native unit tests cover legacy decoding, quantity arithmetic/bounds, backup round trips, personal and friend reports, cent remainders, invalid owners, refund/repayment protection, friend-paid purchases, automatic-entry identity and both notification-confirmation paths. The existing cold-launch UI tests now also check that choosing ownership preserves the unsaved form. Native execution and visual verification require Xcode/iOS; Windows project and syntax checks cannot establish native test success.
