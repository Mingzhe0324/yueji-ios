# Item charge editing and clearer transaction context

Edit items previously rendered only ExpenseChargeDetails, which is absent when the entry has no saved charge metadata. It now renders the same optional SST / Service Charge input section as the main expense editor. Stored subtotal/rates load into the fields. New charge metadata requires a user-supplied subtotal; existing payment or item amounts are not assumed tax-exclusive. Actual payment stays unchanged until the user explicitly applies the calculated total. Item prices and ownership remain tax-exclusive, with charges proportionally allocated by the existing accounting model.

The focused item editor saves charges, source-currency gross and items together, preserving record identity, quote, source and split-history IDs. Validation rejects payment/subtotal mismatches and incompatible item totals. Refund/repayment locks and active settlement validation remain enforced. Fee and payment edits participate in unsaved-dismissal confirmation. Automatic gross payments can be itemized with charges without adding fees again; merely reopening the editor leaves them intact.

Bank repayment rows now preview purchases linked by the saved repayment IDs. A timeline projection builds the required index once off the main actor, including purchases from earlier months. Linked bank settlements and manual settlement rows preview their applied audit lines. Entries are deduplicated by purchase ID; at most two purchase descriptions are shown, followed by the remaining count. Merchant, description and actual item names are used without assigning a guessed purpose to unlinked incoming funds. Amounts, debt allocation, spending and income are unchanged by this display work.

Transaction details lead with a clearly labelled payment or personal share, merchant/description, category/date and expanded items. Tax breakdown follows the items. Repeated merchant/category/payment rows and empty settlement sections are removed; source, account-payment metadata, FX and original notifications are available in More payment information. Refunds, reimbursements, actual split balances and edit/delete actions remain available. Items stay expanded.

Regression coverage checks explicit fee application in the item editor, preserving item prices/IDs, history locks, automatic gross reopening, bank repayment references across months, deduplication, unlinked income and applied settlement audit lines. Windows project and Swift syntax checks do not replace hosted native compilation, XCTest execution, visual review or keyboard/sheet interaction checks.
